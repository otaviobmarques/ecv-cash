Instalar o ECV Cash numa VPS com Traefik

O Traefik do OpenClaw já ocupa as portas 80 e 443 e emite os certificados. O ECV Cash entra ao lado, como um projeto Docker separado, sem alterar nada do que já existe.

flowchart LR
  I[Internet] --> T["Traefik
80 / 443 · HTTPS"]
  T --> C["Caddy do ECV Cash
HTTP interno"]
  C --> W["Telas
app e admin"]
  C --> A["/api"]
  A --> P["API"] --> D[("PostgreSQL")]

Preencha os três campos e os comandos abaixo já saem com os seus valores. Nada é enviado para fora desta página.

0Antes de começar

Entre na VPS e descubra os dados do Traefik. Todos estes comandos só leem informação.

ssh root@IP_DA_VPS
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
docker network ls

Anote o nome do contêiner do Traefik e do OpenClaw. Troque traefik abaixo pelo nome que apareceu:

docker inspect traefik --format '{{range $n,$_ := .NetworkSettings.Networks}}rede: {{$n}}{{"\n"}}{{end}}'
docker inspect traefik --format '{{range .Args}}{{println .}}{{end}}' | grep -E "certificatesresolvers|entrypoints"
Na saída procureVira
a rede do Traefik (ex.: openclaw_default)REDE_TRAEFIK
--certificatesresolvers.NOME.acme…TRAEFIK_CERTRESOLVER = NOME (comum: letsencrypt)
--entrypoints.NOME.address=:443 e :80normalmente websecure e web (já são o padrão)
!

Se o Traefik foi configurado por arquivo (traefik.yml) e não por argumentos, ache o arquivo com docker inspect traefik | grep -i -A3 mounts e leia o nome do certresolver nele.

Veja se há memória livre (o banco e a API pedem cerca de 1 GB) e guarde o estado atual do OpenClaw para comparar no fim:

free -h
docker ps --format '{{.Names}}\t{{.Status}}' | sort > /root/estado-antes.txt
cat /root/estado-antes.txt

Abra também o endereço do OpenClaw no navegador e confirme que está funcionando.

1Apontar o DNS

No painel do domínio (registro.br ou Hostinger), crie dois registros A com o IP da VPS:

NomeTipoValor
appAIP da VPS
adminAIP da VPS

Confira (pode levar de minutos a horas): o resultado deve ser o IP da VPS.

dig +short app.SEUDOMINIO
dig +short admin.SEUDOMINIO
!

Se o seu domínio já serve o OpenClaw, use um subdomínio separado: com ecv.seudominio.com.br como domínio, os registros ficam app.ecv e admin.ecv.

2Baixar o código

O repositório é privado, então a VPS precisa de uma chave só de leitura.

apt-get update && apt-get install -y git
ssh-keygen -t ed25519 -N "" -f ~/.ssh/ecv_deploy -C "vps-ecv-cash"
cat ~/.ssh/ecv_deploy.pub

No GitHub: repositório ecv-cash › Settings › Deploy keys › Add deploy key. Cole a chave pública e não marque “Allow write access”. Depois:

printf 'Host github.com\n  IdentityFile ~/.ssh/ecv_deploy\n  IdentitiesOnly yes\n' >> ~/.ssh/config
git clone git@github.com:otaviobmarques/ecv-cash.git /opt/ecv-cash

3Gerar o .env

cd /opt/ecv-cash/deploy
./gerar-env.sh SEUDOMINIO REDE_TRAEFIK CERTRESOLVER

O script confere se a rede existe e cria o .env com senhas novas, legível só pelo root. Se os entrypoints do seu Traefik forem outros, acrescente no fim os nomes do HTTPS e do HTTP, nessa ordem.

!

Guarde uma cópia do deploy/.env num gerenciador de senhas. Ele tem as senhas do banco e a chave que cifra o 2FA. Sem ele não há como recuperar o sistema.

4Subir

docker compose up -d --build
docker compose ps

A primeira vez leva alguns minutos.

✓

Esperado: db, api e site rodando. O migrar aparece como “exited (0)”: ele só aplica as migrações e sai.

Se o comando reclamar de variável faltando, o .env está incompleto. Compare com .env.exemplo.

5Criar o primeiro usuário interno

docker compose run --rm criar-interno "Seu Nome" seu@email.com PLATAFORMA

A senha provisória aparece uma única vez. Anote. Depois:

  • Abra https://admin.SEUDOMINIO, entre com o e-mail e a senha provisória e configure o aplicativo autenticador (2FA).
  • Crie o primeiro grupo. O link do convite do Administrativo aparece na tela, para você entregar.
  • A pessoa abre o link (https://app.SEUDOMINIO/convite?token=…), define a senha e entra.

O certificado leva até um minuto na primeira visita.

6Conferir que o OpenClaw continua funcionando

docker ps --format '{{.Names}}\t{{.Status}}' | sort > /root/estado-depois.txt
diff /root/estado-antes.txt /root/estado-depois.txt
✓

O diff deve mostrar só linhas novas do ECV Cash (ecv-cash-db-1, ecv-cash-api-1, ecv-cash-site-1) e nenhuma mudança nos contêineres do OpenClaw e do Traefik. Um “Up 3 days” que virou “Up 2 minutes” indica reinício e deve ser investigado.

  • Abra o endereço do OpenClaw e use como de costume.
  • docker logs --tail 50 traefik (use o nome do seu contêiner) não deve ter erros novos. Mensagens com ecv-cash são sobre as rotas do ECV Cash.
  • free -h mostra a memória em uso. No limite, o plano precisa de mais RAM.

Se o OpenClaw tiver qualquer problema, pare só o ECV Cash:

cd /opt/ecv-cash/deploy && docker compose down
✕

Nunca use docker compose down -v: o -v apaga o banco do ECV Cash.

Rotina

Atualizar para a versão nova do GitHub (as migrações rodam sozinhas):

cd /opt/ecv-cash && ./deploy/atualizar.sh

Backup diário às 3h, guardando 14 dias em /var/backups/ecv-cash:

(crontab -l 2>/dev/null; echo '0 3 * * * /opt/ecv-cash/deploy/backup.sh >> /var/log/ecv-backup.log 2>&1') | crontab -
/opt/ecv-cash/deploy/backup.sh

A segunda linha roda um backup agora, para testar. Copie os arquivos para fora do servidor de vez em quando. A restauração está em docs/05-publicacao.md, no repositório.

Logs, dentro de /opt/ecv-cash/deploy:

docker compose logs -f api

Problemas

Página “404 page not found” em app ou admin

O Traefik não achou a rota. Confira se REDE_TRAEFIK é a rede em que o Traefik realmente está e os nomes dos entrypoints. Depois rode docker compose up -d e veja docker logs --tail 100 traefik | grep -i ecv-cash.

Certificado inválido ou aviso do navegador

O DNS ainda não propagou ou o nome do certresolver está errado. Veja docker logs traefik | grep -i -E "acme|certificate".

502 Bad Gateway

O Caddy ou a API não subiu. Rode docker compose ps e docker compose logs api site.

“Origem não permitida” no login

O domínio do .env não bate com o endereço aberto no navegador. Corrija o .env e rode docker compose up -d.

Todo mundo parece ter o mesmo IP nas tentativas de login

A API lê o IP real por dois proxies (Traefik e Caddy), definido por TRUST_PROXY_SALTOS=2 no compose. Se um dia colocarem outro proxy na frente, como a Cloudflare, esse número passa a ser 3.
